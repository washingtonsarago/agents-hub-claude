## ⚠️ Limitação do ambiente (leia primeiro)

Esta análise **não conseguiu consultar o estado ao vivo dos Pull Requests no GitHub**:

- `api.github.com` continua **bloqueado** pela allowlist de egress (`curl` → `HTTP 000`).
- O repositório é **privado** (a página de PRs via web retorna **404/login**) e a sandbox **não tem credenciais** — `git fetch` falha com `could not read Username for 'https://github.com'`. `gh` CLI não está instalado.
- Portanto, a análise se baseia apenas nos **refs do clone local**, congelados no último *fetch* bem-sucedido (branches `feature/*` datadas de **2026-05-07**).

**Consequência:** qualquer PR aberto *depois* desse fetch é invisível aqui. O que segue avalia apenas as branches que ainda aparecem "à frente da `main`" no clone local. Enquanto o ambiente permanecer congelado, este relatório é, por construção, espelho dos runs anteriores. A `main` local, contudo, avançou (último commit `2e2c861 docs: add PR review notes`, 2026-06-17), o que apenas **aumentou** o tamanho dos diffs de reversão das branches stale.

**Para tornar a automação confiável:** liberar `api.github.com` na egress **e** prover um token (PAT/`gh` CLI) à sandbox. Sem isso, os runs diários reanalisam dados estáticos.
